# Co-Founder Shared Context

## What It Is

A setup where two founders (or partners) each have their own self-folder but both contribute to and draw from a single shared business context folder. Each person's AI agent works from the same source of truth without requiring both people to be in the same tool, the same workflow, or even the same conversation.

## Why It Matters

Leadership teams fragment context constantly — one founder knows something the other doesn't, decisions get made without full information, and the AI each person uses only knows their slice of the picture. Shared context solves this at the architectural level: the folder is the living shared brain, not any individual's memory or inbox. Both partners can query it independently and always get the full picture.

## How to Use It

**As a coach:** Useful for co-founder dynamics — it externalises the shared understanding and reduces the reliance on "did we talk about this?" The folder becomes the third party that both can point to.

**As a consultant:** Deliver this as the default architecture for any two-person leadership team. Each founder gets their own self-folder; both write to and read from the shared business folder. The setup doc becomes part of the onboarding playbook.

**As a content creator:** The angle: co-founders spend enormous energy staying aligned. A shared context folder makes alignment a system, not a scheduled meeting.

## Content Angles

- Most co-founder tools (Notion, Slack, email) share documents but not context. This pattern shares the actual intelligence layer.
- The question: "If one of you went dark for a week, could your AI still give your partner the full picture?" If not, your context isn't shared — it's just stored.
- Story: two founders using separate AI setups who keep rediscovering each other's decisions. Then the shared folder model as the fix.
