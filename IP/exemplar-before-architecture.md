# Exemplar Before Architecture

## What It Is

When trying to standardise a messy system, don't start by designing the ideal structure. Find the best existing example — the cleanest folder, the clearest report, the most organised brand — and study what makes it work. Then use that as the template everyone else replicates. The exemplar replaces abstract design with something concrete people can actually copy.

## Why It Matters

Designing the "perfect system" from scratch in a messy organisation almost always fails. It takes too long, nobody agrees, and the result is too abstract to implement. Starting with a real example that already works short-circuits all of that. There's already proof it functions; there's something tangible to point to; and the template comes pre-loaded with practical constraints the abstract design would have missed.

## How to Use It

**As a coach:** When a client is paralysed trying to "figure out the right system," ask them to show you their best current example. Start there. What's already working is almost always a better foundation than what's theoretically correct.

**As a consultant:** In any standardisation or AI-context-building project, the first question is: what's your cleanest existing instance of this? Build the template from that, not from a whiteboard.

**As a content creator:** The cleanest file in your messy folder is your actual system design — you just haven't noticed it yet.

## Content Angles

- The perfect system you design from scratch will never be as good as the messy system that already works.
- Don't design the template; find it. It's already in your best example.
- Standardisation projects fail when they start with the blank page instead of the best existing case.
