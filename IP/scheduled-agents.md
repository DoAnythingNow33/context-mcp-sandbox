# Scheduled Agents

## What It Is

A scheduled agent runs the same workflow logic as a local Claude Code session, but hosted on the Anthropic cloud and triggered on a cron schedule — no terminal open, no manual run, no user present. The logic is identical; only the runtime changes.

## Why It Matters

Most AI workflows built in Claude Code are manually triggered — the user opens a terminal, runs a command, waits. Scheduled agents remove the human from the loop entirely. The same skill that emails a morning research report when Dan types a command can email it at 8am every day without anyone touching anything. This is the difference between a tool and a system: tools require intent, systems run without it. For clients like Jamie, this is the difference between "I built something cool" and "I have something that works for me."

## How to Use It

**As a coach:** The moment a client has a working workflow, ask: "What would need to be true for this to run without you?" That question surfaces whether the workflow is actually embedded or just demonstrated. Scheduled agents are the answer — and the question creates the pull.

**As a consultant:** Natural upgrade path in any Claude Code engagement: (1) build and validate the logic locally, (2) confirm quality with manual runs, (3) move to scheduled agent for autonomous operation. Flag it in session 1 as the destination — clients buy into the build more readily when they can see where it's going.

**As a content creator:** The "set it and forget it" frame is tired. The real angle: most people build automation that still needs them. A scheduled agent is the first honest version of autonomous AI — same thinking, just running while you sleep.
