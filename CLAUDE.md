# CLAUDE.md — Context 2.0

## Architecture

Four core layers:

- **self/** — identity: `beliefs.md`, `goals.md`, `arc.md` (character arc), `identity.md` (current self — MBTI + interests merged in), plus `writing-dna.md`. Built and maintained through Q+A via `/internal-os`. Exists for context + accountability: it holds who Dan is and who he's becoming, so every agent knows.
- **entities/** — everyone and everything Dan is responsible for, split two ways:
  - `entities/people/` — clients + family, one file each (the "client folder")
  - `entities/projects/` — DoAnythingNow business state + `offers/` + engagements
  - People and Projects link to each other (a project lists its People; a person lists their Projects).
- **calendar/** — time structure: daily DPLs, weekly `R-`/`P-` files, monthly and quarterly reviews. The accountability backlog of everything done and not done — feeds strategy weekly, monthly, quarterly.
- **IP/** — the knowledge library: `IP/<slug>.md` + `IP/_index.md` + `IP/_template.md` — every concept, technique, framework, principle, analogy, tool. `content_made` frontmatter flag tracks whether an entry has become content.

Supporting folders:

- **ops/** — operational workflows, one subfolder each. `ops/sales/` documents the prospecting workflow, but the CRM itself lives in Notion (migrated 2026-08-14) — see `ops/sales/context.md`, fed by `/prospect`. `ops/content/` is the output layer — finished content in `linkedin/` and `x/`, each with `Posted/` and `Deferred/`, plus `linkedin-audience.md`. Workflow rules live in `ops/context.md`.
- **meetings/** — structured meeting files. The single source of truth for meetings; links connect them to entities + calendar.
- **actions/** — **frozen archive.** Live actions moved to the Notion **Tasks Tracker** on 2026-09-02 (data source `1e64c614-f809-80b6-944a-000b9e6dfad4`, **Active** view). `done/` + `cancelled/` remain as the pre-migration record; nothing writes there. See `actions/README.md`.
- **scripts/** — deterministic Python utilities for naming, validation, scaffolding, digest.

Skills (slash commands) live in `.claude/commands/`. See tables below.

## Session Rhythm: Orient → Work → Persist

### Orient — Every session, read:

```
self/goals.md     — active threads (always loaded)
_digest.md        — compressed entity states (if exists; replaces individual entity reads)
```

`_digest.md` is generated by `/wrap` after every session. If it exists, read it instead of opening individual entity files — it contains all snapshot frontmatter in one file.

`index.md` is **not** auto-loaded — it is a navigation destination. Open it only when you need to resolve which entity file to read or check the availability/time blocks. This file (CLAUDE.md) is the source of truth that directs you across the folder; `index.md` is just the map you consult on demand.

Run `python scripts/validate_freshness.py` at session open (or before `/weekly-review`) to catch drift — snapshots that haven't absorbed a logged meeting, a stale digest, or an `index.md` date out of sync with its snapshot.

Then load by task type — read the workspace context file first, then the files it specifies:

| Task                       | Read                                                                          | Skip                        | Skills                                                 |     |
| -------------------------- | ----------------------------------------------------------------------------- | --------------------------- | ------------------------------------------------------ | --- |
| Client work / coaching     | `entities/context.md` + relevant `people/`/`projects/` file                   | `self/`, `IP/`, `calendar/` | `/meeting`, `/summary`, `/client-vault`                |     |
| Meeting ingest             | `IP/_index.md`, relevant entity file                                          | `self/`, `content/`         | `/meeting` (→ `/pull-ip`, `/summary`, `/action-items`) |     |
| Content creation           | `ops/content/context.md`, `self/writing-dna.md`, `IP/_index.md`, `_digest.md` | `calendar/`, `entities/`    | `/written-content`                                     |     |
| IP development             | `IP/context.md`, `IP/_index.md`                                               | `ops/content/`, `calendar/` | `/pull-ip`                                             |     |
| Daily capture / DPL        | `calendar/context.md`, previous DPL, current `P-` plan                        | `entities/`, `IP/`          | `/dpl`                                                 |     |
| Weekly review / planning   | `calendar/context.md`, latest `R-` and `P-` files                             | `IP/`, `content/`           | `/weekly-review`, `/written-content`                   |     |
| Self / coaching reflection | `self/context.md`, `self/arc.md`, `self/identity.md`                          | `entities/`, `content/`     | `/internal-os`                                         |     |
| Cross-layer synthesis      | `self/arc.md`, `self/goals.md`, `_digest.md`, latest `R-`/`P-`                | `IP/`, `content/`           | `/synthesis`                                           |     |
| Session close              | Already loaded context                                                        | —                           | `/wrap`                                                |     |

### Work

Draw on loaded context naturally. When an entity state shifts, a new tension emerges, or an open question surfaces — capture it immediately in the relevant entity file. Don't wait until end of session.

**Sessions are conversational, writes are invisible.** The point of this vault is to give Dan — and Hermes — fast, accurate context to make better decisions. That context gets built through talking: Dan describes what's going on, Claude asks follow-up questions mapped to the snapshot schema (`current_focus`, `open_questions`, `tensions`, `next_actions`), and reflects back what's tension-worthy. The actual file writes (entity snapshots, `index.md`, meetings, IP, actions) happen as background work, not narrated inline — no "updating X file now," no visible Read/Edit tool output cluttering the conversation. Dispatch vault writes as background agents and surface only a short outcome line once done, or nothing at all if routine.

### Persist — Before ending any session

- [ ] Write or update the daily log in `calendar/[year]/[quarter]/daily/YYYY-MM-DD.md`
- [ ] Update `index.md` if any entity state changed
- [ ] Update the relevant `entities/people/` or `entities/projects/` file
- [ ] Update `self/goals.md` if active threads shifted
- [ ] Add any new client/external meetings to `meetings/` and link from calendar + entity file

## Linking Convention

Meeting files live in `meetings/` — the single source of truth. Links create connections without duplication.

**Each meeting file** has a backlink header:
```
← [[entities/people/growify]] | [[calendar/2026/Q2/april-2026]]
```

**Each entity file** (people or projects) has a Meetings section:
```
## Meetings
- [[2026-04-26-growify-call-2]]
```

**Each calendar month file** has the same `## Meetings` section.

**People ↔ Projects**: each `projects/` file has a `## People` section; each `people/` file has a `## Projects` section. Use bare wikilinks (`[[growify]]`) — Obsidian resolves by filename.

## Snapshot Schema

Entity files (people + projects, excluding `offers/` profiles) use this frontmatter:

```yaml
---
entity: [Name]
type: snapshot
last_updated: YYYY-MM-DD
current_state: "[One paragraph]"
current_focus:
  - "Priority 1"
open_questions:
  - "What are we trying to figure out?"
tensions:
  - "Things pulling in different directions"
next_actions:
  - "Concrete next steps"
---
```

`generate_digest.py` picks up every file with `type: snapshot`. Offer files in `entities/projects/offers/` use `type: profile` and are excluded from the digest. Update `index.md` every time a snapshot changes.

## Hermes (always-on assistant) + GitHub Actions (scheduled layer)

Hermes is an always-on AI assistant with SSH access to the GitHub repo. GitHub is the sync layer — the vault lives at `~/Desktop/Context 2.0` and syncs via GitHub (GitHub Desktop on the Mac; Hermes pushes and pulls over SSH).

**Ad-hoc capture:** Dan messages Hermes any time during the day. Hermes routes each update into the correct file per the "Where Things Go" table — no queue file, no pipeline. Routing rules: `docs/hermes-capture.md`.

**Scheduled messages run as GitHub Actions** (`.github/workflows/`), sent via Discord webhook — Hermes crons proved awkward, so the proactive layer lives here:

**Dan is never prompted or interviewed by the scheduled layer.** He said so explicitly (2026-08-25): he takes responsibility for sending messages and voice notes to Discord when he has something. Scheduled messages tell him things; they never ask him things, and they never reference scores, streaks, or how many days he logged.

- `morning-debrief.yml` (daily 7am UTC) — runs `claude -p` over `self/goals.md`, `_digest.md`, `_health.md` and `actions/` to write a directive brief: what matters today, three concrete moves, and one thing quietly needing attention. Ends by inviting a voice note. No questions.
- `weekly-synthesis.yml` (Sundays 6pm UTC) — runs `/synthesis` headless and read-only (Step 4 persistence skipped), posting the cross-layer patterns Dan values — the between-the-lines connections no single file shows.
- `evening-debrief.yml` — **retired 2026-08-25.** Dan self-reports in the evening. Recoverable via git if ever wanted.
- `self-heal.yml` (Sundays 4pm UTC) — the autonomous maintenance loop: runs `/maintain` headless (applies Dan's answered `_maintenance-interview.md`, heals the vault, writes a fresh interview), runs `generate_review_questions.py` for Monday's `/weekly-review`, commits everything, messages the summary. Needs `CLAUDE_CODE_OAUTH_TOKEN` (or `ANTHROPIC_API_KEY`) repo secret; all three workflows need `DISCORD_WEBHOOK`.

## Scripts (deterministic layer)

| Script | When to run | What it does |
|--------|-------------|--------------|
| `python scripts/validate_naming.py` | Auto in `/weekly-review` / anytime | Scans files for naming violations, reports fixes (`--fix` to auto-rename) |
| `python scripts/extract_carry_forwards.py --days 7` | Before `/weekly-review` | Extracts past week's daily-log sections into one file |
| `python scripts/generate_digest.py` | Auto after `/wrap` | Regenerates `_digest.md` from `type: snapshot` entity files |
| `python scripts/validate_links.py` | Before `/weekly-review` / anytime | Checks meeting files have matching cross-links in entity + month files |
| `python scripts/validate_freshness.py` | Session open / before `/weekly-review` | Flags drift: snapshots behind their meetings, a stale digest, or `index.md` dates out of sync |
| `python scripts/system_health.py` | Auto nightly via `evening-debrief.yml` / before `/maintain` / on demand | Deterministic scan, no scoring. Surfaces what's going quiet (entities, rotting actions >30d, stale `doing/`, parked threads), loose ends (unfiled `next_actions`), and vault mechanics (index drift, unused IP, missing tensions, orphan meetings) → writes `_health.md`. Dates actions by git history, not mtime. Always exits 0. Zero tokens; `/maintain` reads its output. |
| `python scripts/scaffold_quarter.py [year] [Q]` | Start of new quarter | Creates the quarter folder structure (`--dry-run` to preview) |
| `python scripts/generate_review_questions.py` | Auto Sundays via `self-heal.yml` / on demand | Inspects the week just ended, writes `_review-questions.md` (gap questions phrased by `claude -p`) to the weekly folder. `/weekly-review` reads it Monday. See `docs/DEFERRED.md` §3 |

## Voice

Warm, opinionated, direct. Say what makes more sense and why — don't list options. Name tensions. Connect self↔entity patterns when they emerge. Ground all recommendations in loaded context: available time, entity state, arc direction. Generic advice is worse than no advice.
